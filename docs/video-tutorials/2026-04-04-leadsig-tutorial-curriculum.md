# LeadSig Short Video Tutorial Curriculum (V1)

## Audience And Goal
- Primary audience: New owners/admins
- Objective: Feature coverage across the core product in short, actionable videos
- Batch size: 9 videos (within 8-10 target)
- Detail level: Production-ready outlines (not full scripts)

## Tutorial Entry Interface (Use This For Every Video)
Each tutorial entry must use this exact field order:
1. Video Title
2. Why This Matters
3. User Outcome
4. Feature Areas Covered
5. Length Target
6. Demo Flow
7. Talking Points
8. Shot List
9. Common Mistakes to Address
10. End CTA

## Sequencing, Dependencies, And Recording Data
- Recommended viewing order: 1 to 9 in this document
- Dependency rule: Complete all `Core Day-1` videos before `Core Week-1`, then `Advanced Setup`
- Recording environment required:
- One owner/admin test account with sample data
- At least 6 leads across statuses (`new`, `contacted`, `qualified`, `pending_approval`, `rejected`, `archived`)
- At least 6 jobs across statuses (`unscheduled`, `scheduled`, `in_progress`, `completed`) including one unassigned and one needing invoice
- At least 2 estimates (one draft/needs review, one accepted)
- At least 2 invoices (one unpaid/partial and one paid)
- At least 2 payments in history
- One configured service area and availability schedule
- At least 2 crew members for assignment/filter demos
- One job with a client portal link and visible timeline activity

## 1) Dashboard Orientation And Daily Workflow
- Video Title: Dashboard Orientation And Daily Workflow
- Why This Matters: New owners need a reliable "start-here" page to triage leads, jobs, approvals, and client follow-ups fast.
- User Outcome: User can open dashboard, interpret priority cards/sections, and choose top 3 next actions for the day.
- Feature Areas Covered: Dashboard, quick actions, qualified leads section, today's jobs section, awaiting approval section, clients needing attention.
- Length Target: 90 seconds
- Demo Flow:
- Open `/` (Dashboard)
- Identify greeting, quick stats, and priority sections
- Click a qualified lead card and return
- Click a job card and return
- Use `Add Lead` and `Add Job` entry points
- Talking Points:
- Dashboard is the daily control center
- Priority sections reduce context switching
- Use stats for a fast pipeline/revenue pulse
- Start with time-sensitive items first (approvals and today’s jobs)
- Use quick add buttons when capturing work in real time
- Shot List:
- Full dashboard load state
- Quick stats close-up
- Lead section interaction
- Job section interaction
- Top-right `Add Lead` and `Add Job` buttons
- Common Mistakes to Address:
- Treating dashboard as read-only and not acting from it
- Ignoring pending approval items until end of day
- End CTA: Open your dashboard now and identify the 3 highest-priority actions for today.
- Recommended Order: 1
- Prerequisite Videos: None
- Tier Tag: Core Day-1
- Required Setup State: Dashboard has at least one item in leads, jobs, and approvals sections
- Success Checkpoint: User can name and execute their first priority action directly from dashboard

## 2) Onboarding Source And Data Import
- Video Title: Onboarding Source And Data Import
- Why This Matters: Clean initial data setup reduces manual entry and speeds time-to-value in the first hour.
- User Outcome: User can select previous CRM, import leads/clients/jobs CSVs, and continue into product tutorial flow.
- Feature Areas Covered: Onboarding source, onboarding import, CSV import modals for leads/clients/jobs.
- Length Target: 120 seconds
- Demo Flow:
- Open `/onboarding/source`
- Select previous CRM and continue
- Open `/onboarding/import`
- Run one lead CSV import
- Show optional client/job imports
- Continue to tutorial/home
- Talking Points:
- Pick previous CRM for tailored onboarding context
- Import now for immediate productivity; can import later too
- Use correct CSV type per entity (lead vs client vs job)
- Confirm import completion indicators before continuing
- Keep sample templates clean and mapped correctly
- Shot List:
- CRM selection step
- Import landing state
- Leads CSV modal open + import completion state
- Client and job import options
- Continue action to tutorial/home
- Common Mistakes to Address:
- Importing client rows into leads file format
- Skipping import verification and assuming data is present
- End CTA: Import one CSV now (leads recommended) and verify records appear in the correct section.
- Recommended Order: 2
- Prerequisite Videos: None
- Tier Tag: Core Day-1
- Required Setup State: Valid sample CSV files for leads, clients, and jobs
- Success Checkpoint: User completes at least one successful CSV import and sees records in-app

## 3) Leads Pipeline: Qualify, Pending/Rejected, Conversion Actions
- Video Title: Leads Pipeline: Qualify, Pending/Rejected, Conversion Actions
- Why This Matters: Lead handling speed and consistency directly impacts close rate and missed-opportunity risk.
- User Outcome: User can filter/search leads, process pending/rejected queues, and qualify a lead to move it forward.
- Feature Areas Covered: Leads list, status tabs, pending approval page, rejected leads page, lead qualification action.
- Length Target: 110 seconds
- Demo Flow:
- Open `/leads`
- Use search + tabs (`all`, `new`, `contacted`, `qualified`, `archive`)
- Open pending approval shortcut and return
- Open rejected leads shortcut and return
- Qualify one lead from list
- Talking Points:
- Keep the pipeline organized by status, not memory
- Pending and rejected are high-signal exception queues
- Qualification should be a deliberate go/no-go step
- Search and tabs are the fastest path to targeted actions
- Archive only when lifecycle is truly complete
- Shot List:
- Leads page with tab counts
- Pending and rejected quick-access buttons
- Qualify action on a lead card
- Filtered views by status
- Common Mistakes to Address:
- Leaving leads in `new` too long without decision
- Confusing rejected leads with archived/completed leads
- End CTA: Qualify one real lead and clear at least one pending or rejected item.
- Recommended Order: 3
- Prerequisite Videos: 1
- Tier Tag: Core Day-1
- Required Setup State: Leads exist in new, pending approval, rejected, and qualified paths
- Success Checkpoint: User qualifies one lead and correctly navigates pending/rejected queues

## 4) Jobs Lifecycle: Create, Statuses, Unassigned, Needs-Invoice
- Video Title: Jobs Lifecycle: Create, Statuses, Unassigned, Needs-Invoice
- Why This Matters: Job lifecycle visibility prevents assignment gaps, overdue work, and lost revenue.
- User Outcome: User can create a job and interpret operational alert badges to resolve blockers quickly.
- Feature Areas Covered: Jobs list, create job dialog, status tabs, unassigned badge, needs-invoice badge, overdue badge.
- Length Target: 110 seconds
- Demo Flow:
- Open `/jobs`
- Create a new job from action button
- Walk through status tabs and counts
- Toggle unassigned alert and explain meaning
- Toggle needs-invoice alert and explain next billing action
- Talking Points:
- Jobs page is execution control for in-flight work
- Status tabs reflect workload stage and bottlenecks
- Unassigned means responsibility gap that needs immediate fix
- Needs-invoice means revenue follow-up is pending
- Overdue badge highlights schedule risk
- Shot List:
- Jobs list header and revenue subtitle
- Create job dialog
- Alert badge interactions (unassigned, needs invoice, overdue)
- Status tab switching
- Common Mistakes to Address:
- Creating jobs without assigning ownership promptly
- Completing work but delaying invoice handoff
- End CTA: Create one job and resolve one alert badge condition today.
- Recommended Order: 4
- Prerequisite Videos: 1, 3
- Tier Tag: Core Day-1
- Required Setup State: At least one unassigned job, one completed job without invoice, and one overdue job
- Success Checkpoint: User creates one job and clears at least one lifecycle alert

## 5) Schedule: Week/Month, Crew Filters, Recurring Handling
- Video Title: Schedule: Week/Month, Crew Filters, Recurring Handling
- Why This Matters: Reliable scheduling prevents missed appointments and crew allocation errors.
- User Outcome: User can navigate week/month calendar views, filter by crew member, and handle recurring projections.
- Feature Areas Covered: Schedule page, week/month view toggle, date navigation, crew filter, recurring projected dates.
- Length Target: 120 seconds
- Demo Flow:
- Open `/schedule`
- Switch between week and month view
- Navigate forward/backward in time
- Filter to one crew member and back to all crew
- Open projected recurring instance and create one
- Talking Points:
- Use week view for dispatch decisions; month for capacity planning
- Crew filters isolate workload and accountability
- Recurring projections help preempt schedule collisions
- Keep days off and availability aligned with real operations
- Confirm created recurring instances appear in schedule
- Shot List:
- Week-to-month view transition
- Date range navigation controls
- Crew filter dropdown
- Recurring projected card and create action
- Common Mistakes to Address:
- Managing recurring jobs manually instead of using projected instances
- Ignoring crew-specific filters and overloading one person
- End CTA: Schedule one job in week view and create one recurring instance.
- Recommended Order: 5
- Prerequisite Videos: 4
- Tier Tag: Core Week-1
- Required Setup State: Multiple scheduled jobs, at least one recurring template, at least two crew members
- Success Checkpoint: User changes view, filters crew, and creates one recurring instance

## Production Standards
- Each video covers one job-to-be-done only.
- Start with a consistent opener: "In this video, you’ll do X."
- End with a consistent closer: "Next best action is Y."
- Keep all videos between 60 and 120 seconds.
- Include one measurable success checkpoint in each video.
- Use realistic sample data names and statuses shown in product UI.
- Show at least one click path from nav to task completion in every video.
